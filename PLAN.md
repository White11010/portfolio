# PLAN.md — Рефакторинг портфолио, переход на Next.js и полноценная локализация

> Документ описывает результаты ревью и пошаговый план работ. Каждый шаг содержит
> **описание**, **что сделать** и **критерии готовности (Definition of Done)**.
> Шаги упорядочены так, чтобы их можно было выполнять последовательно без блокировок.

## 0. Текущее состояние проекта (результаты ревью)

### 0.1. Стек и структура

- **Сборка:** Vite 5 + React 18 + TypeScript 5 (SPA).
- **Стили:** Tailwind CSS 3 (`darkMode: 'class'`), кастомные компоненты в `index.css`.
- **Роутинг:** `react-router-dom` v7 (`BrowserRouter`, клиентский роутинг).
- **Иконки:** `lucide-react`.
- **Данные:** статические TS-массивы `src/data/projects.ts`, `src/data/posts.ts`.
- **Контексты:** `ThemeContext` (тёмная тема), `LanguageContext` (язык — заглушка).
- **Происхождение:** проект сгенерирован из шаблона Bolt (`.bolt/`, бейдж в README,
  имя пакета `vite-react-typescript-starter`).

```
src/
  App.tsx                 # BrowserRouter + провайдеры + Routes
  main.tsx                # createRoot
  index.css               # Tailwind + кастомные компонентные классы
  components/             # Header, Footer, ProjectCard, BlogPostCard, Tag
  contexts/               # ThemeContext, LanguageContext
  data/                   # projects.ts, posts.ts (англ. контент)
  pages/                  # Home, Projects, ProjectDetail, Blog, BlogPost, About
```

### 0.2. Слабые места и технический долг (с прицелом на Next.js)

| # | Проблема | Риск при переходе на Next.js |
|---|----------|------------------------------|
| W1 | `react-router-dom` (`BrowserRouter`, `Routes`, `useParams`, `useLocation`) | Несовместим с App Router — нужна полная замена на файловый роутинг. |
| W2 | `ThemeContext` применяет класс `dark` в `useEffect` | FOUC и hydration mismatch при SSR — нужен inline-скрипт до гидратации. |
| W3 | Прямой доступ к `window`/`localStorage`/`document` в инициализаторах `useState` | Часть гард-ов есть, но логику нужно сделать SSR-safe (`'use client'`, чтение в `useEffect`). |
| W4 | Самописный markdown-парсер в `BlogPostPage.tsx` (регэкспы, ~150 строк) | Хрупкий, тяжело поддерживать; на SSR лучше рендерить через библиотеку (remark/MDX). |
| W5 | Нет per-route метаданных (SEO) — единственный `<title>` в `index.html` | Next.js Metadata API даёт SEO бесплатно; сейчас не используется. |
| W6 | Неиспользуемая зависимость `@supabase/supabase-js` | Мёртвая зависимость, увеличивает bundle и поверхность атаки. |
| W7 | `key={pathname}` на `<main>` форсит полный ремоунт страницы | Лишние перерисовки; в App Router не нужно. |
| W8 | Нет 404-страницы (только инлайновые "not found"), нет error boundary | В Next.js — `not-found.tsx` / `error.tsx`. |
| W9 | CSS-класс `animate-fade-in` используется в `Header`, но **не объявлен** в Tailwind config | Анимация не работает — баг уже сейчас. |
| W10 | Нет Prettier, тестов, CI, строгих алиасов импортов | База качества кода отсутствует. |
| W11 | `text-secondary` (#6B7280) без dark-варианта | Возможны проблемы контраста в тёмной теме (WCAG). |
| W12 | Контент захардкожен в JSX (англ.) | Блокирует локализацию (см. раздел 0.4). |

### 0.3. Проблемы мобильной/тачскрин вёрстки

| # | Проблема | Где | Влияние |
|---|----------|-----|---------|
| M1 | Кнопки в шапке `h-8 w-8` (32px) — **меньше 44px** | `Header.tsx` (язык/тема/меню) | Маленькие тач-таргеты, тяжело попасть пальцем (Apple HIG/Material — мин. 44px). |
| M2 | Кнопка "копировать код" `opacity-0 group-hover:opacity-100` | `BlogPostPage.tsx` (`CodeBlock`) | На тач-устройствах нет hover → кнопка недоступна. |
| M3 | `min-h-screen` (100vh) | `App.tsx` Layout | На мобильных браузерах 100vh скачет из-за адресной строки — лучше `100dvh`. |
| M4 | Нет учёта `safe-area-inset` (вырезы/«чёлка») | шапка, мобильное меню, футер | Контент может уезжать под системные элементы на iOS. |
| M5 | `scroll-behavior: smooth` без `prefers-reduced-motion` | `index.css` | Игнор системной настройки уменьшения движения (a11y). |
| M6 | Нет `-webkit-tap-highlight-color` / `touch-action` | глобально | Серая «вспышка» при тапе, неаккуратные жесты. |
| M7 | Полноэкранное мобильное меню без блокировки фокуса / Esc | `Header.tsx` | A11y: фокус «утекает», нет закрытия по Escape. |
| M8 | Горизонтальный скролл тегов без видимой подсказки прокрутки | `BlogPage.tsx` | Не очевидно, что список скроллится (UX). |
| M9 | Бейдж `text-[10px]` ("External") | `BlogPostCard.tsx` | Очень мелкий текст на мобильных. |

### 0.4. Состояние локализации (критично)

- `LanguageContext` хранит `lang` (`'en' | 'ru'`) и `toggle()`, переключатель EN/RU есть
  в шапке, **но переключатель ни на что не влияет** — нет `t()`, нет словарей.
- **100% UI-текстов захардкожены на английском** в JSX (Header nav, Hero, заголовки секций,
  кнопки, Footer, About и т.д.).
- Контент данных (`projects.ts`, `posts.ts`) — только английский, без структуры под перевод.
- `<html lang="en">` зафиксирован статически; `lang` не синхронизируется с выбором.
- В тексте About заявлено «I write in both English and Russian», но переводов нет.

**Вывод:** локализация присутствует только как UI-каркас. Нужна полноценная i18n-инфраструктура
и перевод всей статики на EN и RU.

## Этап 3. Миграция на Next.js (App Router) + SSR

**Описание.** Перевести SPA на Next.js с серверным рендерингом, заменив `react-router-dom`
файловым роутингом и добавив SEO-метаданные.

**Что сделать:**
1. Установить `next` (latest), обновить `package.json` scripts (`dev/build/start/lint`).
2. Создать структуру App Router:
   ```
   app/
     layout.tsx              # <html lang>, провайдеры, Header/Footer
     page.tsx                # Home
     projects/page.tsx
     projects/[slug]/page.tsx
     blog/page.tsx
     blog/[slug]/page.tsx
     about/page.tsx
     not-found.tsx
     error.tsx
   ```
3. Заменить роутинг:
   - `Link`/`NavLink` (react-router) → `next/link` + `usePathname`.
   - `useParams`/`useLocation` → пропсы `params` серверных компонентов / `usePathname`.
   - Удалить `react-router-dom`.
4. Пометить интерактивные компоненты `'use client'` (Header, провайдеры, `CodeBlock`,
   фильтр блога, переключатели).
5. Решить **W2/W3**: добавить inline-скрипт в `layout.tsx`, выставляющий класс темы и `lang`
   до гидратации (анти-FOUC); чтение `localStorage` оставить в `useEffect`.
6. Использовать `generateStaticParams` для `[slug]`-маршрутов (проекты, посты).
7. Добавить per-route `metadata` / `generateMetadata` (title, description, OG) — закрывает **W5**.
8. Перенести глобальные стили (`index.css`) и `tailwind.config` (обновить `content` под `app/`).
9. Перенести статику (`/cv-ru.pdf`, `/cv-en.pdf`, favicon) в `public/`.
10. Убрать `key={pathname}` (**W7**), `index.html`, `vite.config.ts`, vite-зависимости.

**Критерии готовности:**
- [ ] `next build` проходит; страницы рендерятся как SSR/SSG (проверка: «View Source»
      содержит контент, а не пустой `#root`).
- [ ] Все маршруты (`/`, `/projects`, `/projects/:slug`, `/blog`, `/blog/:slug`, `/about`)
      работают, навигация без перезагрузки.
- [ ] `react-router-dom` и Vite удалены из зависимостей.
- [ ] Тёмная тема применяется без видимой вспышки при первой загрузке (нет FOUC).
- [ ] У каждой страницы корректные `<title>`/`<meta>`; для постов/проектов — динамические.
- [ ] 404 показывает `not-found.tsx`.

## Этап 4. Полноценная локализация EN/RU

**Описание.** Построить i18n-инфраструктуру и перевести **всю статику** (UI + контент данных)
на английский и русский.

**Что сделать:**
1. Выбрать подход: маршруты с локалью `app/[locale]/...` + библиотека (`next-intl`)
   **или** лёгкий self-made словарь + cookie/`localStorage`. Рекомендация: `next-intl`
   (SSR-совместима, поддерживает `<html lang>`, форматирование дат/чисел).
2. Создать словари `messages/en.json`, `messages/ru.json` для **всех** UI-строк:
   навигация, Hero, заголовки секций, кнопки, Footer, About, состояния «не найдено»,
   подписи и aria-label.
3. Перевести контент данных. Изменить модель `projects.ts`/`posts.ts` на локализованную, например:
   ```ts
   interface LocalizedText { en: string; ru: string }
   interface Project { slug: string; title: LocalizedText; description: LocalizedText; /* ... */ }
   ```
   и предоставить русские переводы для всех проектов и **всех постов блога** (включая `body`).
4. Связать переключатель языка с реальной сменой локали (URL/cookie), синхронизировать
   `<html lang>` (закрывает оставшуюся часть локализации из 0.4).
5. Локализовать форматирование дат постов (`Intl.DateTimeFormat`) и метаданные (`title`/OG)
   для каждой локали.
6. Настроить `generateStaticParams` под локали; обновить ссылки/`sitemap` при наличии.
7. Решить SEO для двух языков: `hreflang`, локализованные метаданные.

**Критерии готовности:**
- [ ] Ни одной захардкоженной пользовательской строки в JSX — всё через `t()`/словари
      (проверка грепом по типовым английским фразам).
- [ ] Переключатель EN/RU реально меняет язык всего интерфейса **и** контента (проекты, посты).
- [ ] `messages/en.json` и `messages/ru.json` имеют идентичный набор ключей (нет пропусков).
- [ ] Все проекты и посты переведены на RU и EN (включая тела статей).
- [ ] `<html lang>` совпадает с активной локалью; даты отформатированы по локали.
- [ ] Прямой переход по локализованному URL отдаёт корректный язык на SSR.

## Этап 5. Исправление мобильной/тачскрин вёрстки и a11y

**Описание.** Закрыть проблемы M1–M9 и довести мобильный UX до продакшн-уровня.

**Что сделать:**
1. Увеличить тач-таргеты в шапке до ≥44×44px (**M1**); сохранить визуальный размер иконки,
   расширив область нажатия паддингом.
2. Сделать кнопку копирования кода видимой на тач-устройствах (**M2**): показывать всегда
   на `(hover: none)` или по `focus`/`active`.
3. Заменить `min-h-screen` на `min-h-[100dvh]` (с фолбэком) (**M3**).
4. Добавить поддержку `env(safe-area-inset-*)` в шапке/меню/футере (**M4**).
5. Обернуть `scroll-behavior: smooth` и анимации в `@media (prefers-reduced-motion)` (**M5**).
6. Глобально задать `-webkit-tap-highlight-color: transparent` и аккуратные `touch-action` (**M6**).
7. Мобильное меню: focus trap, закрытие по `Escape`, `aria-modal`, возврат фокуса (**M7**).
8. Добавить визуальную подсказку прокрутки тегов (fade-маска по краям) (**M8**).
9. Поднять минимальный размер мелких подписей (**M9**), проверить контраст `text-secondary`
   в тёмной теме (**W11**) по WCAG AA.
10. Прогнать страницы в DevTools (iPhone SE/14, Pixel) и Lighthouse (mobile).

**Критерии готовности:**
- [ ] Все интерактивные элементы ≥44×44px (проверка в DevTools).
- [ ] Копирование кода работает тапом на мобильном.
- [ ] Нет горизонтального скролла и «прыжков» высоты на iOS Safari/Chrome Android.
- [ ] Контент не перекрывается вырезами на устройствах с notch.
- [ ] Lighthouse Mobile: Accessibility ≥ 95, нет ошибок контраста.
- [ ] Меню закрывается по Escape, фокус заперт внутри при открытии.
